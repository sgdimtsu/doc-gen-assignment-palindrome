# doc-gen-assignment

A small config-driven pipeline that turns a client's source material into an advice report. Start
with `PROJECT_GUIDANCE.md`; it describes the exercise.

## Setup

```bash
# clone your fork, then:
cp .env.example .env          # put your OpenAI key in .env
uv sync                       # or: pip install -e .
```

## Run

```bash
uv run python -m agent_pipeline.generate --client client_01_clean
# report is written to outputs/client_01_clean.md - This will run for client_01, we would recommend reviewing data/code before running on other clients.
```

Available clients live under `data/`:

- `client_01_clean`
- `client_02_medium`
- `client_03_hard`
- `client_04_stretch` (large and messy on purpose; a deliberate stretch)

## Extraction agent

Run the new extraction stage separately from the baseline report generator above.
Use Python 3.10 or newer and install the project in your active environment:

```bash
python -m pip install -e ".[dev]"
python -m agent_pipeline.extract --client client_01_clean
```

The command makes live OpenAI API calls using `OPENAI_API_KEY` from the environment
or the repository's `.env`. Existing environment variables take precedence. Model
selection is `--model`, then `EXTRACTION_MODEL`, then `OPENAI_MODEL`, with
`gpt-4o-mini` as the initial default. The model must support tools, image input and
structured outputs. No reconciliation or advice report is generated by this command.

The agent reads `report_request.docx` and `template_spec.md` first, then uses its
reading tools to inspect the remaining evidence. Instructions are in
`EXTRACTION_SCHEMA.md`; the model's output schema is `config/extraction_schema.json`.

Outputs are stored beneath `outputs/<client>/`:

- `extraction.json`: latest complete, code-enriched extraction.
- `extraction_manifest.json`: latest run's completion state, coverage, errors,
  usage and paths. Check this first: after a partial run, `extraction.json` can
  still belong to a previous complete run.
- `runs/<run_id>/`: per-run manifests and complete results.
- `diagnostics/<run_id>/`: available partial results and invalid response diagnostics.

Exit status is 0 for complete execution, 1 for partial/failed execution and 2 for
invalid command arguments. Complete execution does not guarantee factual accuracy;
inspect the extracted evidence against the sources.

Use `--help` for model, tool-call, retry, timeout and output limits, and for custom
input/output, instructions and schema paths. For example:

```bash
python -m agent_pipeline.extract --client client_01_clean --max-model-calls 20 --max-tool-calls 40
python -m pytest -q
```

Tests use simulated responses and do not call the API.

## How it fits together

```
config/template_config.json          the report definition: sections, prompts, inclusion rules
        │
        ▼
src/agent_pipeline/generate.py       reads the client's files, then for each section decides
        │                            inclusion and fills its prompts from the client's data
        ▼
src/document_formatter/formatting.py assembles the sections into the final .md document
        │
        ▼
outputs/<client>.md
```

## The pipeline is deliberately minimal

What you are given is the smallest setup that runs end to end. It works, but it is naive: one model
call per section, every file in the client folder dumped into every prompt whether or not it is
relevant, a single model, and no tools. Improving it is part of the task; weigh speed, cost, and
effectiveness (see `PROJECT_GUIDANCE.md`). Most of your work will be in
`config/template_config.json`; the pipeline code is yours to improve too.
